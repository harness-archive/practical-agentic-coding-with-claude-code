# MoAi - ADK 워크플로

## 1. plan - run - sync 핵심 워크플로우
### 1. /moai plan
- 구현 전 상세 설계 SPEC 문서 생성 단계
- 코드베이스 탐색 -> 요구사항 분석 -> SPEC 문서 생서 (EARS 형식)

### 2. /moai run
- SPEC 문서 기반 코드 생성
- SPEC 분석 & 실행 계획 -> DDD/TDD 구현 -> TRUST 5 품질 검증

### 3. /moai sync
- 코드 변경 사항과 SPEC 문서, 프로젝트 문서간 동기화
- 문서 생성 -> README/CHANGELOG 업데이트 -> PR 생성

<br>

## 2. 서브에이전트 심층 활용
- MoAI-ADK는 Sub-Agent와 Agent Teams 이중 실행 모드를 지원한다.
- 서브에이전트를 호출하는 유일한 수단은 Agent 도구이다.
  - subagent_type
  - prompt
  - model
  - max_turns
  - run_in_background
- 사용자 요청이 MoAI를 거쳐 Agent 도구로 전달
- `/moai run SPEC-AUTH-001 --solo`  : Sub-Agent 모드로 실행

## 4. 스킬
- MoAI-ADK에서 스킬은 특정 도메인의 전문 지식을 구조화한 지식 모듈이다.
- 스킬은 9개의 카테고리로 분류되어있다. moai-{category}-{name}
  - Foundation : 철학, 개발 방법론, 핵심 규칙을 정의
    - moai-foundation-core : SPEC 기반 TDD/DDD, TRUST 5 프레임워크, 실행 규칙
    - moai-foundation-claude : Claude Code 확장 패턴 (Skills, Agents, Hooks 등)
  - Language : 16개 스킬, 언어별 패턴
  - Workflow : SPEC 기반 개발 사이클 자동화
  - Domain : 백엔드, DB, 프론트엔드 등 기술 도메인별 전문 지식
  - Platform : 클라우드, 배포 플랫폼 통합

<br>

## 5. 토큰
- 모든 스킬을 한 번에 로드하면 토큰이 낭비되므로, 필요한 만큼만 단계적으로 로드
1. 1단계는 스킬당 약 100 토큰만 사용하여 메타데이터등 최소 정보만 로드
2. 2단계는 트리거 조건이 매칭되면 스킬 문서 전체 로드 ~15,000 토큰 사용
3. 3단계는 modules/ 디렉토리에 저장된 심층 참조 문서로 구성되며 토큰은 가변적

<br>

## 6. 스킬 트리거
- 스킬이 1 -> 2단계로 전환되는 시점은 트리거 시스템이 결정한다.
- 트리거는 4가지 조건으로 구성되며 하나라도 매칭되면 스킬이 활성화된다.
1. 키워드 감지 : 사용자 프롬프트에 특정 단어를 감지하여 연관 스킬 로드
2. 에이전트 호출 : 특정 에이전트가 호출될 때 연관된 스킬을 로드
3. 워크플로우(phases) 단계 : Plan/Run/Sync 단계에 따라 로드
4. 언어 감지 : 작업 중인 파일의 프로그래밍 언어에 따라 로드

<br>

## 7. 훅 시스템
- MoAI - ADK 를 작동시키는 핵심 중 하나는 훅 시스템이다.
- MoAI - ADK는 가장 빈번하게 활용되는 이벤트들을 중심으로 자동화 파이프라인을 구축한다.

| PostToolUse | post_tool__code_formatter.py, post_tool__linter.py, post_tool__ast_grep_scan.py, post_tool__lsp_diagnostic.py |
| PreCompact | pre_compact__save_context.py |
| SessionEnd | session_end__auto_cleanup.py |
| Stop | stop__loop_controller.py |
| TaskCompleted | 태스크 완료 검증 |
