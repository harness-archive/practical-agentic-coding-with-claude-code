# 챕터 8, 클로드 코드와 MoAI-ADK
- 바이브 코딩은 집을 짓는 것과 같다.
- 문제없이 빠르게 집이 점차 완성되어가지만 배관이 어딨는지, 전선은 어떻게 되어있는지 모르게된다.
- 프로젝트가 복잡하면, 맥략을 유실하거나, 품질의 비결정성, 기존 코드 파괴, 유지보수 불가능의 문제가 생긴다.


## 8.1 에이전트 하네스, MoAI-ADK
- MoAI-ADK는 에이전트간 상호작용을 수행하는 에이전트 하네스이다.
- SDD 기반으로 개발하며, 이는 맥락 유실 문제를 해결한다.
- TDD, DDD 이진 방법론을 적용하여 기존 코드 파괴와 유지보수 불가능성 문제를 해결한다.
- Trust-5 품질 프레임워크이다. Test, Readable, Unified, Secured, Trackable을 추구한다.

## 8.2 하네스 엔지니어링
- MoAI-ADK는 에이전트가 코드를 작성하는 대신, 에이전트가 작동할 환경을 설계하는 하네스 엔지니어링을 구현한다.
- 하네스 엔지니어링 핵심 원칙은 실수 재발을 구조적으로 차단하는 것이다.
- 에이전트가 실수하거나 잘못 동작하면 단발성 수정이 아니라 환경 자체를 개선한다.

### 8.2.1 MoAI-ADK 명령어
| 구성 요소 | 설명 | 명령어 |
|-----------|------|---------|
| **Self-Verify Loop** | 에이전트가 코드 작성 → 테스트 → 실패 → 수정 → 통과 사이클을 자율적으로 수행 | `/moai loop` |
| **Context Map** | 코드베이스 아키텍처 맵과 문서가 에이전트에 항상 제공 | `/moai codemaps` |
| **Session Persistence** | `progress.md`가 완료된 단계를 세션 간 추적하며, 중단된 실행이 자동으로 재개 | `/moai run SPEC-XXX` |
| **Failing Checklist** | 모든 인수 기준이 실행 시작 시 대기 작업으로 등록되고, 구현 완료 시 완료로 표시 | `/moai run SPEC-XXX` |
| **Language-Agnostic** | 18개 언어 지원. 언어를 자동 감지하고 올바른 LSP, 린터, 테스트, 커버리지를 선택 | 모든 워크플로우 |
| **Garbage Collection** | 죽은 코드, AI Slop, 미사용 import를 주기적으로 스캔 및 제거 | `/moai clean` |
| **Scaffolding First** | 구현 전에 빈 파일 스텁을 생성하여 엔트로피를 방지 | `/moai run SPEC-XXX` |

## 8.3 MoAI-ADK 기본 워크플로우
plan → run → sync 워크플로우로 동작.
1. plan : 코드 베이스 탐색, 요구사항 분석, 스펙 문서 생성
2. run : 스펙 분석, 실행 계획 수립, DDD/TDD 구현, TRUST-5
3. sync : API 문서 생성, README 업데이트, PR 생성


## 8.4 MoAI-ADK 실행 엔진
MoAI-ADK를 설치하면 프로젝트에 다음과 같은 구조가 생성된다.
```
my-project/
├── CLAUDE.md                  # MoAI의 실행 지침서
├── .claude/
│   ├── agents/moai/           # 28개 AI 에이전트 정의
│   ├── skills/moai-*/         # 52개 스킬 모듈
│   ├── hooks/moai/            # 자동화 훅 스크립트
│   └── rules/moai/            # 코딩 규칙 및 표준
└── .moai/
    ├── config/                # MoAI 설정 파일
    │   └── sections/
    │       └── quality.yaml   # TRUST 5 품질 설정
    ├── specs/                 # SPEC 문서 저장소
    │   └── SPEC-XXX/
    │       └── spec.md
    └── memory/                # 세션 간 컨텍스트 유지
```

## 8.5 MoAI-ADK 4계층 아키텍쳐
1. Foundation 계층 : 최하위 계층, core, claude, philosopher, quality, context 스킬로 구성된다.
2. Workflow 계층 : 개발 워크플로우를 정의, spec, project, ddd, tdd, testing, worktree 등 스킬로 구성
3. Domain 계층 : 기술 도메인별 전문 지식 제공, backend, frontend, database 도메인 스킬과 언어별 스킬, 프로젝트의 기술 스택에 맞게 로드
4. Application 계층 : 개발자가 직접 사용하는 인터페이스, /moai 슬래시 명령어, 에이전트 정의 등

## 8.6 CLAUDE.md
MoAI가 읽는 실행 지침서. 총 15개의 섹션으로 구성된다.
1. 핵심 정체성 : MoAI 오케스트레이터의 역할과 HARD 규칙을 정의
2. 요청 처리 파이프라인 : 사용자 요청을 분석하고 라우팅하는 4단계 파이프라인
3. 명령어 참조 : MoAI-ADK의 3가지 명령어 유형을 정의
4. 그외 섹션들은 생략, 사용시 정리

## 8.7 Rules 시스템
.claude/rules/ 디렉토리에는 조건부로 로드되는 세부 규칙이 저장된다.
```
.claude/rules/moai/
├── core/                          # 핵심 원칙
│   └── moai-constitution.md       # TRUST 5, 핵심 규칙
├── development/                   # 개발 표준
│   ├── skill-authoring.md         # 스킬 작성 가이드
│   └── coding-standards.md        # 코딩 표준
├── workflow/                      # 워크플로우
│   ├── workflow-modes.md          # Plan/Run/Sync 정의
│   └── spec-workflow.md           # SPEC 워크플로우
└── languages/                     # 언어별 규칙 (16개)
    ├── python.md
    ├── typescript.md
```

| 디렉토리 | 파일 | 로드 조건 |
|----------|------|-----------|
| `core/` | `moai-constitution.md` | 항상 로드 |
| `development/` | `skill-authoring.md` | 스킬 관련 작업 시 |
| `development/` | `coding-standards.md` | 코드 작업 시 |
| `workflow/` | `workflow-modes.md` | 워크플로우 명령 시 |
| `workflow/` | `spec-workflow.md` | SPEC 관련 작업 시 |
| `languages/` | `python.md` 등 | 해당 언어 파일 수정 시 |
