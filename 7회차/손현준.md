# 클로드 코드 실전 가이드: 7장 자동화

7장에서는 클로드 코드를 단순히 대화형 도구로 쓰는 것을 넘어, 외부 시스템과 연결하고 반복 작업을 시스템화하는 **'자동화'**의 모든 것을 다룹니다. 비대화형 모드를 활용한 스크립트 작성, 생애 주기에 맞춰 실행되는 훅(Hooks), 외부 도구와 통신하는 MCP, 그리고 이 모든 것을 묶어 배포하는 플러그인(Plugin) 시스템의 핵심 개념과 실무 활용법을 정리했습니다.

## 1. 비대화형 모드와 스크립트 자동화
비대화형 모드는 클로드 코드를 대화형 UI 없이 프로그래밍 방식으로 실행할 수 있게 해 주며, 셸 스크립트, CI/CD 파이프라인, cron 작업 등에 AI 기능을 결합할 때 사용됩니다.

*   **핵심 제어 플래그**:
    *   `-p` (또는 `--print`): 대화창을 열지 않고 결과를 즉시 표준 출력으로 반환합니다.
    *   `--allowedTools` / `--disallowedTools`: 실행 중 클로드가 사용할 수 있는 도구를 제한하여 권한을 제어합니다.
    *   `--output-format json`: 결과를 `text` 대신 JSON 형식으로 반환받습니다. 결과에는 비용(`total_cost_usd`), 소요 시간, 세션 식별자(`session_id`) 등이 포함되어 프로그래밍 방식의 후처리에 필수적입니다.
    *   `-c` (`--continue`) 및 `-r` (`--resume` 세션ID): 여러 단계로 나뉜 복잡한 스크립트를 구현할 때, 이전 대화 컨텍스트를 이어나가기 위해 사용합니다.
*   **구조화된 출력 (`--json-schema`)**: 클로드의 자연어 응답을 미리 정의된 JSON 스키마에 맞추어 강제로 구조화합니다. 이를 통해 파이프라인 연동 시 파싱 오류를 원천 차단할 수 있습니다.
*   **CI/CD 환경 고려사항**: GitHub Actions나 GitLab CI에 통합할 때는 시크릿 변수(API 키 등) 보안, `timeout` 명령어를 통한 강제 종료 대책, 예산 초과를 막기 위한 턴 수 제한(`--max-turns`) 등이 반드시 설정되어야 합니다.

## 2. 이벤트 기반 훅(Hooks) 시스템
클로드 코드의 실행 사이클(예: 세션 시작, 도구 사용 전/후 등 14개 시점)에 개발자가 정의한 자동화 로직을 결정론적으로 심을 수 있는 이벤트 시스템입니다.

*   **3가지 훅 타입 (Type)**:
    1.  **command**: 셸 명령을 직접 실행합니다. (예: 린터 실행, 코드 자동 포매팅). 오래 걸리는 작업은 `"async": true`를 설정해 백그라운드에서 비동기로 실행할 수도 있습니다.
    2.  **prompt**: 훅의 입력값을 LLM에 보내 단일 턴 평가를 받습니다. (예: "클로드가 작업을 중단해도 되는지 논리적으로 평가하라").
    3.  **agent**: 실제 테스트 파일이나 복잡한 환경을 다중 턴으로 검사해야 할 때 서브에이전트에게 평가를 위임합니다.
*   **종료 코드와 권한 통제**: 훅 스크립트에서 **종료 코드 0**을 반환하면 성공으로 처리되지만, **종료 코드 2**를 반환하면 '차단 오류'로 간주되어 클로드의 도구 호출이 즉각 차단되거나 권한이 거부되며 stderr 메시지가 피드백으로 돌아갑니다.
*   **💡 꿀팁: 스마트 하이브리드 백업 (Git 활용)**: `rm`이나 `mv` 같은 셸(Bash) 명령어 실행은 클로드 코드의 기본 체크포인팅으로 복구할 수 없습니다. 이를 보완하기 위해 **Pre-bash 훅에서 `git stash`로 현재 상태를 임시 백업**하고, **Post-bash 훅에서 실제 파일 변경이 일어났을 때만 빈 커밋(Empty Commit)을 남기도록 설정**하면, 안전성과 깔끔한 깃 히스토리를 모두 확보할 수 있습니다.

## 3. MCP 통합을 통한 외부 세계 연결
MCP(Model Context Protocol)는 로컬 환경에 국한된 클로드 코드의 능력을 노션(Notion), 깃허브(GitHub), 피그마(Figma), Sentry, 데이터베이스 등 다양한 클라우드 및 외부 서비스와 단일 인터페이스로 통신할 수 있게 확장해 줍니다.

*   **3가지 네트워크 전송 방식**:
    *   **stdio**: 네트워크 개입 없이 로컬에서 빠르고 안정적으로 통신합니다 (로컬 DB나 로컬 스크립트에 적합).
    *   **HTTP**: 원격 REST API 기반 통신 시 사용하며 인증 헤더(Bearer 토큰)를 지원합니다.
    *   **SSE**: 레거시 원격 서버를 지원하기 위한 방식으로 현재는 권장되지 않습니다.
*   **환경 변수 기반의 안전한 보안**: `.mcp.json` 파일을 깃에 커밋하여 팀과 공유할 때, 민감한 API 키는 하드코딩하지 않고 `${API_KEY}` 형태의 환경 변수 확장을 사용해야 합니다.
*   **동적 리소스 호출**: MCP 서버가 노출하는 특정 리소스는 대화창에서 `@github:issue://123` 형태로 직관적으로 멘션하여 프롬프트에 활용할 수 있습니다.

## 4. 플러그인(Plugin) 시스템과 마켓플레이스
명령어, 서브에이전트, 스킬, 훅, MCP 구성을 각각 관리하지 않고 **단일 패키지로 묶어(플러그인 5대 컴포넌트) 배포하고 재사용**할 수 있도록 하는 확장 생태계입니다.

*   **구조와 마켓플레이스**: 플러그인은 메타데이터를 담은 `plugin.json` 파일을 필수로 가지며, 앤트로픽 공식 마켓플레이스뿐만 아니라 팀의 프라이빗 깃허브 저장소나 특정 로컬 폴더를 마켓플레이스로 등록해 사용할 수도 있습니다.
*   **권한 및 설정 범위**: 플러그인 적용 범위는 사용자 전역(`user`), 프로젝트 종속(`project`), 로컬 전용(`local`), 기업 중앙 제어(`managed`) 등 네 가지 계층으로 나뉘어 관리됩니다.
*   **플러그인 커스텀 개발 핵심 가이드**:
    *   **절대 경로 변수 사용**: 플러그인 내부에 포함된 셸 스크립트나 구성 파일을 참조할 때는 반드시 **`${CLAUDE_PLUGIN_ROOT}` 환경 변수를 사용**해야 합니다. 경로를 하드코딩하면 다른 개발자의 환경에서 플러그인이 로드될 때 에러가 발생합니다.
    *   **빠른 로컬 테스트 환경 (`dev-marketplace`)**: 플러그인 코드를 매번 원격에 배포하지 않고 테스트하려면, 로컬에 `dev-marketplace` 디렉터리를 만들고 이를 클로드 코드 마켓플레이스로 추가한 뒤 설치하는 방식을 활용하세요.
    *   **캐시 주의사항**: 클로드 코드는 설치 시 플러그인 원본을 캐시 디렉터리로 복사하므로, 플러그인 코드를 개발 중 수정했다면 반드시 `/plugin uninstall` 후 다시 설치해야 변경 사항이 반영됩니다.
