# Claude Code 7장 "자동화" 쉬운 설명 정리 (p.191~253)

## 이 장이 다루는 것

6장까지는 클로드 코드 "혼자" 잘 쓰는 법(대화, 상태 관리)을 다뤘다면, 7장은 클로드 코드를 **외부 시스템과 연결하고, 사람이 매번 시키지 않아도 알아서 돌아가게 만드는 법**을 다룹니다.

네 파트로 구성됩니다.

1. **7-1 비대화형 모드**: 클로드 코드를 "대화창 없이" 스크립트/파이프라인에서 프로그램처럼 호출하는 법
2. **7-2 훅(Hooks) 시스템**: 클로드가 특정 행동을 하는 순간마다 "무조건 실행되는" 내 명령을 끼워 넣는 법
3. **7-3 MCP 통합**: 깃허브·노션·데이터베이스 같은 외부 서비스를 클로드의 "도구"로 연결하는 법
4. **7-4 플러그인 시스템**: 위 기능들(명령어·훅·MCP 등)을 하나의 패키지로 묶어 팀·커뮤니티에 배포하는 법

쉽게 비유하면, 7-1은 "심부름 시키기", 7-2는 "특정 순간마다 울리는 자동 알람/필터 설치", 7-3은 "외부 서비스에 만능 어댑터 꽂기", 7-4는 "그렇게 만든 설정 묶음을 설치 패키지로 포장하기"입니다.

## 7-1 비대화형 모드와 스크립트 자동화 (p.191~200)

### 비대화형 모드란?

평소 쓰는 클로드 코드는 "질문 → 답변 → 확인"을 주고받는 **대화형** 모드입니다. 반면 자동화 파이프라인(cron, CI/CD 등)에는 사람이 옆에서 확인해주는 과정이 없습니다. 이때 `-p`(`--print`) 플래그로 **비대화형 모드**를 씁니다: 프롬프트를 던지면 결과만 받고 끝나는 방식입니다.

```bash
$ claude -p "이 코드베이스의 구조를 설명해 줘."
```

> **쉽게 말하면**: 대화형이 "챗봇과 카톡"이라면, 비대화형은 "자판기"입니다. 대화 없이 입력 → 결과만 딱 받습니다.

**활용 예시 (그림 7-1)**: cron(정기 분석), 깃 훅(커밋 전 검사), 슬랙 봇(질문 응답), 모니터링 시스템(이상 감지) — 모두 `claude -p`로 클로드를 호출하고, 결과는 알림/보고서·자동 수정·데이터 저장으로 이어집니다.

### 주요 플래그

| 플래그 | 역할 |
|---|---|
| `--allowedTools "Bash,Read"` | 사용 가능한 도구를 제한 (안전벨트 역할) |
| `--disallowedTools "mcp__github"` | 특정 도구만 차단 |
| `--permission-mode acceptEdits`/`bypassPermissions`/`dontAsk` | 파일 편집 확인 방식 결정 (자동 승인 / 전부 건너뜀 / 전부 거부) |
| `--mcp-config <file>` | MCP 설정을 파일에서 로드 |
| `--max-turns 3` | 도구 호출 반복 횟수(턴) 제한 → 비용/시간 통제 |
| `--append-system-prompt "..."` | 기존 지침에 역할을 추가 (권장) |
| `--system-prompt "..."` | 기본 지침을 통째로 교체 (안전장치도 사라져 위험) |
| `--verbose` | 상세 로그 출력 |

`--allowedTools`/`--disallowedTools`는 내장 도구(Bash, Read, Write 등)뿐 아니라 `mcp__서버이름` 형식으로 MCP 도구도 지정 가능합니다.

### 입출력 형식

- **출력**: 텍스트(기본, 사람용) / **JSON**(`--output-format json`, `is_error`·`total_cost_usd`·`session_id` 등 메타데이터 포함, 프로그램 파싱용 필수) / **스트리밍 JSON**(`stream-json`, 실시간 모니터링용)
- **입력**: 인수로 직접 전달, `echo ... | claude -p`로 stdin 전달, `cat file | claude -p`로 파일 내용 전달

### 다중 턴 세션

`--continue`(`-c`)는 가장 최근 세션을 자동으로 이어가고, `--resume`(`-r`)은 특정 세션 ID를 지정해 재개합니다.
```bash
session_id=$(claude -p "분석 시작" --output-format json | jq -r '.session_id')
claude -r "$session_id" "추가 분석 수행" --no-interactive
```

### 실전 패턴 3가지

모두 **"역할 부여 + 도구 권한 제한 + JSON 출력"**의 조합입니다.

- **SRE 인시던트 봇**: 장애 설명을 넣으면 "SRE 전문가" 역할로 진단·조치를 제안 (`--append-system-prompt` + 모니터링 MCP 도구 허용)
- **자동 보안 리뷰**: `gh pr diff`로 PR 변경분을 가져와 "보안 엔지니어" 역할로 검토, 읽기 전용 도구만 허용
- **다중 턴 법률 어시스턴트**: 세션을 유지하며 계약서 검토 → 규정 준수 확인 → 요약 생성을 단계별로 진행

### CI/CD 파이프라인 연동

깃허브 액션 등에서 클로드를 비대화형으로 호출해 자동 리뷰·감사·문서화를 수행합니다. 신경 쓸 5가지: **인증**(API 키는 시크릿으로), **타임아웃**(`timeout` 명령), **오류 처리**(`is_error` 필드 확인), **비용 관리**(`--max-turns`, `total_cost_usd` 모니터링), **속도 제한**(요청 사이 `sleep`).

```yaml
- name: Claude Code Review
  uses: anthropics/claude-code-action@v1
  with:
    prompt: "이 PR을 리뷰하고 보안 취약점을 확인해 줘."
    output_format: json
    max_turns: 10
```

### 그 외 알아둘 것

- **다중 턴 세션 관리**: 첫 호출에서 세션 ID를 뽑아두고, 이후 `--resume`으로 이어가며 "코드 작성 → 테스트 → 결과 전달해 수정"처럼 단계별 검증 워크플로를 구성
- **에이전트 SDK**: `-p` 플래그 + 파이썬/타입스크립트 SDK를 아우르는 상위 개념. SDK는 언어에 맞는 구조화된 응답(콜백 등)을 제공해 복잡한 시스템에 유리
- **`--json-schema`**: 응답을 내가 정한 JSON 스키마에 강제로 맞춤 → 뒷단 프로그램의 파싱 오류 방지

**사용 시 체크리스트**: JSON 출력 사용 / 종료 코드·stderr로 오류 처리 / 세션으로 맥락 유지 / `timeout`으로 무한 대기 방지 / 요청 사이 `sleep`으로 속도 제한 존중. **비용 관리**는 프롬프트 간결화, 필요한 파일만 분석, `--max-turns` 제한, 결과 캐싱으로 합니다.

## 7-2 훅(Hooks) 시스템 (p.201~226)

### 훅이란

훅은 클로드 생애 주기의 **정해진 시점**에 자동 실행되는 커스텀 셸 명령·LLM 프롬프트·에이전트 작업입니다. 핵심은 **"AI 판단"에 기대지 않고 특정 작업이 반드시 실행되도록 보장**한다는 점입니다.

> **쉽게 말하면**: "포맷팅해 줘"라고 부탁하면 AI가 까먹을 수 있지만, 훅으로 등록하면 매번 무조건 실행됩니다. 훅은 "약속"이 아니라 "자동 반사 신경"입니다.

**훅의 3가지 타입**

| 타입 | 하는 일 | 적합한 상황 |
|---|---|---|
| `command` | bash 명령 직접 실행 | 포맷터·린터처럼 규칙이 정해진 작업 |
| `prompt` | LLM에 프롬프트 전달, 단일 턴 평가 (`{"ok":true/false}` 응답) | 단순 규칙으로 안 되는 판단 |
| `agent` | 서브에이전트 생성, Read/Grep/Glob 등으로 다중 턴 검증(최대 50턴) | 실제 파일·테스트 결과 검사 |
| `http` | 지정 URL로 이벤트를 POST 전송 | 외부 감사·로깅·알림 시스템 연동 |

`command`/`http`는 `"async": true`로 백그라운드 실행도 가능(완료 대기 없이 다음 턴에 결과 전달, 차단·결정 불가).

### 생애 주기와 훅 이벤트 (그림 7-2, 표 7-1)

```
세션 시작 → 사용자 프롬프트 → 도구 호출 준비 → (권한 필요?) → 도구 실행
  → (성공?) → 결과/실패 처리 → (더 작업?) → 응답 완료 → 세션 종료
```

| 이벤트 | 발생 시점 |
|---|---|
| SessionStart | 세션 시작/재개 (`startup`/`resume`/`clear`/`compact`) |
| UserPromptSubmit | 프롬프트 제출 직후, 처리 전 |
| PreToolUse | 도구 호출 직전 (**차단 가능**) |
| PermissionRequest | 권한 승인 대화상자 표시 시 |
| PostToolUse / PostToolUseFailure | 도구 호출 성공 후 / 실패 후 |
| Notification | 알림 전송 시 (차단 불가) |
| SubagentStart / SubagentStop | 서브에이전트 생성 시 / 종료 시 |
| Stop | 메인 클로드 응답 완료 시 (사용자 중단 시 미발생) |
| TeammateIdle / TaskCompleted | 팀원 유휴 전환 직전 / 작업 완료 표시 직전 (품질 게이트용) |
| InstructionsLoaded | CLAUDE.md 등 규칙 파일 로드 시 |
| ConfigChange | 설정 파일 변경 시 |
| WorktreeCreate / WorktreeRemove | 작업 트리 생성/제거 시 |
| PreCompact | 컨텍스트 압축 직전 |
| SessionEnd | 세션 종료 시 (차단 불가) |

모든 이벤트는 stdin으로 JSON을 넘겨줍니다(공통 필드: `session_id`, `transcript_path`, `cwd`, `permission_mode`, `hook_event_name`).

**매처(matcher)**는 훅 실행 조건을 정하는 정규식입니다. `PreToolUse`류는 도구 이름(`Edit|Write`, `mcp__server__.*` 등)에, `SessionStart`는 시작 방식에, `Notification`은 알림 유형에 매칭됩니다. `UserPromptSubmit`/`Stop`/`TeammateIdle`/`TaskCompleted`는 매처를 지원하지 않고 항상 실행됩니다.

### 종료 코드와 결정 제어 (그림 7-3)

훅 결과는 **종료 코드** 또는 **JSON 출력**으로 전달됩니다.

- **0** = 성공 (stdout의 JSON을 파싱)
- **2** = 차단 오류, stderr를 클로드에게 전달. `PreToolUse`(도구 차단), `PermissionRequest`(권한 거부), `UserPromptSubmit`(프롬프트 차단), `Stop`/`SubagentStop`(종료 방지), `TeammateIdle`/`TaskCompleted`(전환·완료 방지)에서만 실제로 "차단" 효과가 있음. `PostToolUse` 등 나머지 이벤트에서는 차단 효과 없이 피드백만 전달됨
- **기타(1, 3...)** = 비차단 오류, 상세 모드에서만 표시

JSON 출력 시 공통 필드로 `continue`(중단 여부), `stopReason`, `suppressOutput`, `systemMessage`가 있고, 이벤트별로 `decision:"block"`+`reason` / `permissionDecision`(allow·deny·ask) / `decision.behavior`(allow·deny) 세 가지 패턴 중 하나를 씁니다.

### 훅 설정 방법

설정 파일은 `~/.claude/settings.json`(사용자) → `.claude/settings.json`(프로젝트) → `.claude/settings.local.json`(로컬) → 엔터프라이즈 정책 → 플러그인 `hooks/hooks.json` → 스킬/에이전트 프론트매터, 이렇게 여러 레벨에 존재합니다. 구조는 **이벤트 선택 → 매처로 필터링 → 핸들러 정의** 3단계입니다.

```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{ "type": "command", "command": ".claude/hooks/block-rm.sh" }]
    }]
  }
}
```

프론트매터 훅(스킬/에이전트 YAML에 직접 정의)은 해당 컴포넌트가 활성화된 동안만 동작하고, 전역 훅과 상호 배타적이지 않아 **둘 다 정의되면 모두 실행**됩니다. `once: true`로 세션당 1회만 실행되게 할 수 있습니다.

### 실전 훅 예제 (요약)

- **위험한 명령 차단**: `PreToolUse`에서 `rm -rf` 포함 시 `permissionDecision: deny` 반환
- **자동 포매팅**: `PostToolUse`(matcher `Edit|Write`)에서 `.ts`/`.tsx` 파일이면 `npx prettier --write`
- **민감 파일 보호**: `.env`, `.git/` 경로 편집을 `PreToolUse`에서 차단
- **세션 로깅**: `SessionStart`/`SessionEnd`에서 로그 파일에 타임스탬프 기록
- **LLM 판단형 Stop 훅**: 대화가 정말 끝났는지 프롬프트 훅으로 평가 후 종료 허용

### 보안 유의 사항 (그림 7-4)

훅은 **내 계정 권한으로 자동 실행**되므로 위험할 수 있습니다. ① 입력값을 맹목적으로 신뢰하지 말 것(검증/살균) ② 셸 변수는 항상 `"$VAR"`로 인용 ③ 경로에서 `..` 확인해 경로 순회 차단 ④ 스크립트는 절대 경로나 `$CLAUDE_PROJECT_DIR` 사용 ⑤ `.env`, `.git/`, 키 파일은 건너뛰기.

디버깅은 `claude --debug`(어떤 훅이 매칭됐는지, 종료 코드 등을 로그로 확인) 또는 `Ctrl+O`로 상세 모드를 켭니다.

### 체크포인팅 보완 (pre-bash/post-bash 훅)

6장의 체크포인팅은 Read/Write/Edit 같은 직접 파일 도구만 추적하고, `Bash`로 실행한 `rm`/`mv`/`cp`는 복구할 수 없습니다. 해결책은 **`pre-bash` 훅에서 위험한 명령이면 `git stash`로 백업**하고, **`post-bash` 훅에서 실제 변경(`git diff --quiet`)이 있을 때만 커밋 후 stash pop**하는 스마트 하이브리드 전략입니다. 실제 변경 있을 때만 커밋해 히스토리가 깔끔하고, 실패 시 즉시 복구 가능하며, 커밋 메시지에 실행된 명령이 남아 추적이 쉽습니다.

## 7-3 MCP 통합 (p.226~233)

### MCP란

MCP(Model Context Protocol)는 AI 에이전트가 **외부 시스템과 상호작용하는 표준 프로토콜**입니다. 서비스마다 다른 API/인증 방식을 배울 필요 없이, MCP 표준만 알면 어떤 서비스든 클로드의 "도구"로 연결됩니다(그림 7-5).

> **쉽게 말하면**: MCP는 "만능 어댑터"입니다. 노션·깃허브·DB마다 연결 방식이 달라도, MCP만 익히면 USB처럼 꽂아 쓸 수 있습니다.

### 전송 방식과 관리

- **stdio**: 로컬 서버(npx 등)와 표준 입출력으로 통신, 가장 빠르고 안정적 — `claude mcp add --transport stdio <name> -- <command>`
- **HTTP**: 원격/클라우드 서버, REST 기반, 인증 헤더 지원 — `claude mcp add --transport http <name> <url>`
- **SSE**: deprecated, 레거시 서버 마이그레이션 전에만 사용

관리 명령: `claude mcp list`/`get`/`remove`, 세션 내 `/mcp`로 상태 확인·OAuth 인증.

**활용 사례**: GitHub(PR 검토·이슈 해결), 데이터베이스 직접 쿼리(로그·매출 분석), 모니터링(Sentry로 오류 진단), 디자인 도구(피그마 → React 컴포넌트 변환).

### 범위와 설정

- **로컬**(`--scope local`, `.claude/settings.local.json`): 민감 정보용, 나만 사용
- **프로젝트**(`--scope project`, `.mcp.json`): 팀 공유, 버전 관리에 커밋
- **사용자**(`--scope user`, `~/.claude/mcp.json`): 모든 프로젝트에서 개인적으로 사용
- 엔터프라이즈는 `managed-mcp.json`으로 `allowedMcpServers`/`deniedMcpServers` 중앙 관리

`.mcp.json`에서 `${VAR}`, `${VAR:-default}` 구문으로 환경 변수를 참조해 API 키를 코드에서 분리할 수 있습니다. 인증은 **OAuth 2.0**(`/mcp` 명령으로 브라우저 인증) 또는 **헤더 기반**(`--header "Authorization: Bearer ..."`) 두 방식입니다. MCP 리소스는 `@github:issue://123`처럼 `@` 멘션으로 참조 가능합니다.

### 훅 × MCP 연동

`PostToolUse` 훅 + MCP로 "파일 변경 시 PR 생성 제안" 같은 자동 알림을, `PreToolUse` 훅으로 특정 조건에서만 MCP 도구(예: 허용된 리포지토리만) 사용하도록 제어할 수 있습니다.

**실전 예시**: 풀스택 개발(그림 7-6, Jira→Figma→DB→GitHub Actions→Vercel→Sentry를 한 세션에서 순환), SaaS 운영(Stripe 결제 분석, SendGrid 이메일, Zendesk 자동 응답 제안).

**유의 사항**: 최소 권한만 부여, API 키는 환경 변수로 분리, 미사용 서버 정리 / 자주 안 쓰는 서버는 필요할 때만 연결, 비용 모니터링 / 외부 서비스 의존이므로 장애 대응책 필요.

## 7-4 플러그인 시스템 (p.234~253)

### 플러그인이란

플러그인은 클로드 코드 핵심을 건드리지 않고 기능을 추가하는 **모듈화된 확장 단위**입니다. 명령어·에이전트·훅·MCP 설정을 하나로 묶어 여러 프로젝트·팀·커뮤니티에 재사용(핵심 가치) 배포할 수 있게 합니다.

> **쉽게 말하면**: 지금까지 배운 비대화형 모드·훅·MCP는 "프로젝트 안에서 설정하는 기능"이었다면, 플러그인은 그 설정들을 **하나로 포장해서 전달하는 설치 패키지**입니다.

### 구조와 plugin.json

모든 플러그인은 `.claude-plugin/plugin.json` 매니페스트가 필수입니다. 필수 필드는 `name`(kebab-case) 하나뿐이고, 나머지(`version`, `description`, `author`, `keywords`, 컴포넌트 경로 등)는 선택이지만 채울수록 좋습니다.

```
my-plugin/
├── .claude-plugin/plugin.json   # 필수 메타데이터
├── commands/hello.md             # 슬래시 명령
├── agents/helper.md              # 서브에이전트
├── skills/my-skill/SKILL.md      # 스킬
├── hooks/hooks.json              # 이벤트 핸들러
└── .mcp.json                     # MCP 서버
```

기본 디렉터리(`commands/`, `agents/`, `skills/`, `hooks/`)는 자동 인식되고, 비표준 위치는 `plugin.json`의 경로 필드로 지정합니다. 플러그인 내부 리소스 참조 시 **절대 경로 대신 `${CLAUDE_PLUGIN_ROOT}` 환경 변수를 반드시 사용**해야 다른 환경에서도 안전하게 동작합니다. `lspServers`(코드 인텔리전스), `outputStyles`(출력 스타일) 필드도 지원됩니다.

### 5대 컴포넌트

| 컴포넌트 | 역할 | 비유 |
|---|---|---|
| 명령어 | `commands/`에 마크다운 배치, `/plugin-name:command` 로 호출(네임스페이싱으로 충돌 방지) | 내가 부르는 단축키 |
| 에이전트 | `agents/`에 정의, 4장의 서브에이전트와 동일 구조 | 전담 부하 직원 |
| 스킬 | `skills/*/SKILL.md`, 3장 스킬 시스템을 패키징 | 배경지식 확장팩 |
| 훅 | `hooks/hooks.json` 또는 인라인, 7-2절과 동일 이벤트·타입 지원 | 자동 반사신경 |
| MCP 서버 | `.mcp.json` 또는 `mcpServers` 필드 | 외부 서비스 어댑터 |

### 설치 범위, 마켓플레이스, 관리 명령어

**설치 범위 4가지**: `user`(전체 프로젝트, 개인용) / `project`(팀 공유, 버전관리 커밋) / `local`(개인 설정, git 제외) / `managed`(기업 IT 중앙관리, 읽기 전용).

**마켓플레이스**는 플러그인 카탈로그입니다. 앤트로픽 공식 마켓플레이스(`claude-plugins-official`)가 기본 등록되어 있고(Code Intelligence/External Integrations/Development Workflows/Output Styles 4개 카테고리), 추가로 깃허브 저장소·일반 Git URL·로컬 디렉터리를 마켓플레이스로 등록할 수 있습니다(`/plugin marketplace add owner/repo`). 마켓플레이스는 `.claude-plugin/marketplace.json`(필수 필드: `name`, `owner`, `plugins`)으로 정의됩니다.

**설치/관리 명령어**:
```bash
> /plugin marketplace add owner/repo        # 마켓플레이스 등록
> /plugin install plugin-name@marketplace   # 설치
> /plugin enable / disable plugin-name@mp   # 켜기/끄기 (제거하지 않고 일시 비활성화)
> /plugin uninstall plugin-name@mp          # 완전 제거
```
팀 프로젝트에서는 `.claude/settings.json`에 마켓플레이스+`installed` 목록을 적어두면, 팀원이 저장소를 클론하고 **신뢰를 명시적으로 승인**할 때 자동 설치됩니다.

**문제 해결**: `claude --debug`로 로드 과정·매니페스트 오류·컴포넌트 등록·MCP 초기화를 확인. 흔한 원인은 JSON 구문 오류, `commands/` 위치 오류, 훅 스크립트 실행 권한 누락(`chmod +x`), `${CLAUDE_PLUGIN_ROOT}` 미사용.

### 실전 예제: 코드 품질 도구 플러그인

팀이 반복하는 작업(린트·테스트·리팩터링·컨벤션)을 하나의 플러그인으로 묶은 예시입니다.

```
code-quality-plugin/
├── .claude-plugin/plugin.json
├── commands/quality-check.md          # "/quality-check"로 종합 품질 검사 트리거
├── agents/refactor-specialist.md      # 복잡한 리팩터링 전담 에이전트
├── skills/team-conventions/SKILL.md   # 네이밍·파일구조·코드스타일 규칙
└── hooks/hooks.json                   # 저장 시 자동 린트(PostToolUse)
```
스킬로 팀 컨벤션을 미리 참고하게 하고, 저장할 때마다 훅이 자동 린트를 돌리고, 명령어로 언제든 종합 점검을 하고, 복잡한 리팩터링은 전문 에이전트에게 위임하는 구조입니다.

**로컬 개발**: `dev-marketplace` 패턴으로 로컬 디렉터리를 임시 마켓플레이스로 등록해 빠르게 반복 테스트합니다(`/plugin marketplace add ./dev-marketplace` → `install` → 수정 후 `uninstall`+재`install`). 플러그인은 설치 시 **캐시 디렉터리로 복사**되므로 원본을 고쳐도 재설치 전까지 반영되지 않고(심볼릭 링크는 예외), `../` 같은 상위 경로 접근은 보안상 차단됩니다.

### 배포와 유의 사항

배포 전 체크리스트: `plugin.json` 메타데이터(`name`/`version`/`description`/`author`) 완비, 전체 컴포넌트 테스트, README 문서화, 라이선스 명시, CHANGELOG 작성.

설계 원칙: **단일 책임**(포매팅·테스트·보안검사는 별도 플러그인으로 분리) / **플러그인 간 의존성 피하기**(공통 기능은 스킬로 분리) / **상대 경로 + `${CLAUDE_PLUGIN_ROOT}` 사용** / **훅 스크립트 실행 권한 부여** / **명확한 에러 메시지 제공**.
